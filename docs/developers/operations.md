# 운영

## 초대는 가입된 이메일만 받는다

`invite_workspace_member` RPC(`supabase/migrations/0019_system_integrity.sql`)는 `auth.users`에서 이메일로 사용자를 찾아 그 계정을 멤버로 추가한다. 가입하지 않은 이메일을 넘기면 "This email has not signed in to Hestia yet" 예외로 거부한다 — 초대장을 보내서 미가입자를 끌어들이는 흐름이 아니다.

동아리 초기 사용 순서:
1. [배포 가이드](../DEPLOYMENT.md)에 따라 Auth 리다이렉트·비공개 Storage·Realtime 설정과 전체 마이그레이션을 준비한다.
2. 대표자가 먼저 로그인하고 온보딩에서 동아리 이름으로 워크스페이스를 만든다. 생성자는 owner가 된다.
3. 구성원들이 각자 한 번 로그인한 뒤, 대표자가 문서의 공유 화면에서 가입한 이메일을 추가한다. 읽기 전용은 viewer, 본문 공동 편집은 editor, 구성원 관리 담당자는 admin을 사용한다. admin 부여는 owner만 가능하다.
4. 서로 다른 권한의 계정으로 문서 열기·공동 편집·버전 기록·복원·이미지·검색을 확인한 뒤 실제 자료를 옮긴다. 문서 소유권과 워크스페이스 소유권은 별개이며, 일반 editor는 본문 공동 편집이 가능해도 다른 사람이 소유한 문서의 버전 기록·복원 권한은 없다.

초대 이메일 발송이나 미가입자를 위한 초대 링크는 아직 구현하지 않았다. 대표자 계정을 공용으로 쓰는 대신 각 구성원을 개별 계정으로 추가한다.

## 과금·배포는 미정

- 무료 한도 인원수, 시트 단가, 플랜 이름은 하나도 정해지지 않았다. 결정 후 별도 반영한다.
- 배포 대상(Supabase 클라우드 vs 셀프호스트)도 미정이고, 이 저장소는 원격 Supabase 프로젝트에 `link`되어 있지 않다.

## 마이그레이션 적용 상태

2026-10-22 로컬 Supabase에는 0026까지 적용됐다. 0019·0020의 기존 부분 적용 이력을 정리하고 0021·0022로 작성자 삭제와 공유 편집 보존을 보정했다. 운영/원격 DB에는 적용하지 않았다. 앱과 DB를 같은 커밋으로 맞추고 기존 편집 탭은 새로고침한다.

단위 테스트 173개, 실제 서비스 통합 검사 53개, 타입 검사와 빌드, SQL 회귀 검사를 통과했다. 독립 브라우저의 실제 로그인·공동 편집·이미지·버전 기록도 확인했다. [최신 로컬 검증 기록](../LOCAL-VALIDATION.md)에 적용 상태와 검증 범위를 기록한다.

## 아직 검증하지 못한 범위

- **외부 운영 환경** — 로컬 실제 서비스와 두 브라우저 검증은 완료했다. 외부 SMTP, Google OAuth, 운영 도메인/네트워크는 검증하지 않았다.
- **장시간 검증** — 비공개 이미지는 인증 다운로드 후 현재 탭의 blob URL로 표시한다. 다인·대용량으로 장시간 사용한 검증은 별도다.
- **브라우저 로컬 저장소 복구의 한계** — `engine/collaboration-recovery.ts`의 스냅샷·`engine/collaboration-sync.ts`의 미전송 작업 큐는 모두 `localStorage`에 쌓인다. 저장소가 막혔거나(프라이빗 모드, 쿼터 초과) 사용 불가능하면 보존을 보장하지 않고 그 사실을 상태 메시지로만 알린다(`store.available`가 `false`일 때). 세대가 바뀐(복원된) 뒤의 미전송 편집은 새 문서에 자동으로 재적용되지 않는다 — 사용자가 직접 복사하거나 `exportRecoveryData`로 내보내야 한다. 같은 브라우저라도 저장소를 지우면(캐시 삭제, 다른 기기) 그 복구 데이터는 사라진다.
- 변경 로그 압축은 구현되어 있지 않다. 로그는 다음 복원까지 계속 늘어난다 — 운영 규모가 커지면 별도 압축 프로토콜이 필요하다.

구성원·역할 관리는 [커스텀 역할 문서](authorization.md)를 참고한다. `members.manage`는 문서 편집을 포함하지 않으며 역할 정의는 소유자만 관리한다.

## 보안 마무리판

현재 스크립트 nonce CSP·TOTP MFA·DB 추가 인증 조건·감사 로그와 관리자 조회 UI를 제공한다. 공동 편집의 본문 방송을 없애고 DB 확인 후 조회하는 `page-v2:` 프로토콜로 전환했다. 비공개 이미지는 서명 URL 대신 인증된 다운로드/blob을 사용한다. 기존 Realtime 캐시도 새 본문 전송에 사용하지 않는다. [현재 검증](../SECURITY-REVIEW.md)·[운영 설정](../PRODUCTION-SECURITY.md)을 기준으로 운영한다.
